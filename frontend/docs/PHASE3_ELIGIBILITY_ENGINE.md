# PHASE 3: 学籍番号解析・履修候補判定

検証日: 2026-08-21

学籍番号解析を `src/services/studentProfile.ts`、履修候補判定を
`src/services/eligibilityEngine.ts` へ分離した。

- NFKC、空白除去、大文字化後に `YY + 3桁 + 所属3文字` を検証する。
- 学籍番号から学生の実在は保証せず、所属判定に個人番号を使わない。
- 実学年があれば推定学年より優先し、所属コードの対象学年矛盾は警告する。
- 専攻、学科共通、学部共通、全学共通、正式開放の順に対象を判定する。
- 未知の個人条件は `conditional`、先の履修年次は `related_future` として保持する。
- 読替後の6桁基本科目番号を2026開講データへJOINし、クラス単位に戻す。
- 判定理由は内部デバッグ結果に保持し、UIへ表示しない。

追加属性の未登録状態では教職・学芸員・司書の登録者限定科目を除外する。
第一言語が未選択の直接エンジン呼び出しは削除せず `conditional` とし、UIでは選択を
必須にした。コース・専修の分類だけを理由に他コース科目を除外しない。

`25001NKU` と `25001NDU` の比較では、候補科目は156件と165件、共通138件、
NKUのみ18件、NDUのみ27件となり、専攻固有科目が相互に混入しないことを
科目番号で検証した。大学院M/D、旧コード、読替、全学共通、明示的所属除外、
形式不正、未知所属もテスト済みのため、PHASE 4へ進んだ。
